# OtbasAI

Instagram-подобный интерфейс поиска ответов об Отбасы банке на FastAPI.

Проект использует готовую матрицу из 10 000 документов, базовую модель BGE-M3
и обученный residual-слой из пакета приложения.

## Локальный запуск через Docker

```bash
docker compose up --build
```

Откройте `http://localhost:8000/`. Первый запуск может загрузить базовую модель
BGE-M3 размером около 2,3 ГБ. Кэш сохраняется в Docker volume `hf-cache`.

API доступно по адресу `http://localhost:8000/docs`.

## Локальный запуск без Docker

Проверенная конфигурация: Linux x86-64, Python 3.12 и PyTorch 2.7.1 CPU.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

После первичной загрузки модели можно отключить сеть:

```bash
HF_HUB_OFFLINE=1 python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

## Основные маршруты

- `GET /` — веб-интерфейс;
- `POST /search` — поиск похожих ответов;
- `GET /topics` — темы корпуса;
- `GET /health` — состояние модели;
- `GET /docs` — документация API.

Пример запроса:

```json
{
  "question": "Продал квартиру в другом регионе два года назад. Учитывается ли она при постановке на жилищный учёт?",
  "top_k": 3
}
```

## Модель

Сервис не генерирует ответы. Он кодирует вопрос фиксированной ревизией
`BAAI/bge-m3` и ищет ближайшие документы в уже готовом индексе из 10 000
вопросов; обученный residual projection имеет размерность 1024 и ранг 64.
Модель, ревизия, версия индекса, версия приложения и параметры поиска
зафиксированы в `config.yaml`. `assets-10k-v1` — локальная версия набора
пакетных assets, поскольку отдельной версии индекса в метаданных нет.

Запрос принимает `question` (1–4000 символов), `top_k` (1–10, по умолчанию 3),
`dedupe` (по умолчанию `true`), а также необязательные `low_threshold` и
`high_threshold`, которыми можно переопределить значения из `config.yaml`.
Дедупликация группирует результаты по точному тексту ответа и оставляет вопрос
с максимальным cosine в каждой группе.

Ответ `/search` содержит `matches`, `found` и `confidence`. Значения
`confidence`: `high` при cosine не ниже 0.60, `medium` между порогами, `low`
ниже `confidence.low_threshold` (по умолчанию 0.30). При `low` API возвращает
`found: false`; если `retrieval.return_matches_on_low` равно `true` (по
умолчанию), `matches` содержит ближайшие результаты, иначе список пуст.
Интерфейс показывает низкоуверенный результат как предупреждение, не выдавая
его за подтверждённый ответ. Порог `high_threshold` по умолчанию равен 0.60.
`cosine` — сходство в диапазоне от −1 до 1, не вероятность корректности.
Текст пользовательского вопроса в JSONL-лог не записывается.

Поиск не проверяет все юридические условия и может вернуть похожий, но
неприменимый пример, особенно при различии чисел, дат или оснований.
Проверочный набор содержит только 16 test- и 36 validation-запросов; список
близких вопросов без ответа в `eval/eval.json` требует ручного подтверждения.

## Деплой

Рекомендуется для production разместить контейнер на VPS за Nginx или Traefik
с HTTPS и постоянным volume для Hugging Face-кэша. Подойдут VPS с 4–8 ГБ RAM,
40 ГБ диска и Docker.

Минимальная схема:

```bash
docker compose up -d --build
```

Для публичного сервиса дополнительно настройте HTTPS, ограничение частоты запросов,
мониторинг и резервное копирование данных.

## Проверка в облаке

Следующие команды запускайте в облачной Linux-среде, не на локальном компьютере:

```bash
python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.7.1
python -m pip install -r requirements-dev.txt
pytest -m "not slow"
pytest -m slow
python eval/evaluate.py
```

`pytest -m slow` и `evaluate.py` загружают BGE-M3 при отсутствии кэша. Они
используют готовый индекс и не перестраивают корпусные эмбеддинги.
